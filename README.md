# MAMMATE — Mammoth Express Store Inventory System

휴대폰 번호로 로그인하는 모바일 웹앱입니다. 직원은 매장의 전체 자재 카탈로그(기본자재/식자재)에서 발주가 필요한 항목을 골라 정상/긴급/품절 상태와 수량을 담고, 사장님은 그렇게 제출된 발주 리스트를 소분류별로 모아서 확인·체크·공유합니다.

- **로그인**: 휴대폰 번호를 입력하면 끝 — 문자(SMS) 인증은 없고, 번호+이름으로 계정을 만듭니다. 같은 번호로 로그인하면 어떤 기기에서든 같은 이름·같은 역할로 들어가져서 항상 동기화돼요 (아래 "계정 시스템" 참고)
- **직원 화면**: 타이핑 없이 **대분류(기본자재/식자재) → 소분류(컵/뚜껑/파우더/시럽·소스/베이스 등) → 자재 선택** 순서로 눌러 내려가면서, 각 자재마다 "정상 발주 / 긴급 / 품절" 중 하나를 고르고 **수량**·메모를 남깁니다. 체크만으로는 사장님 화면에 바로 올라가지 않고, **"기본자재 발주 요청하기" / "식자재 발주 요청하기" 버튼을 각각 눌러야 최종 제출**됩니다 (제출 전까지는 "미제출", 제출 후엔 "제출됨"으로 표시). 하단 바에서 지금까지 담은 개수를 확인하고, "담은 목록 보기"를 누르면 소분류별로 정리된 화면에서 검토하고 제출할 수 있어요. **최근 7일 칩**으로 지난 며칠 기록도 볼 수 있습니다 (사장님 전용이 아니라 직원도 동일하게 볼 수 있어요)
- **사장님 화면**: 그날 제출된 항목만 대분류 → 소분류 순으로 정리해서 표시 (긴급/품절 항목이 눈에 띄게 구분). 각 항목마다 **"주문완료" 체크박스**가 있어서, 사장님이 실제로 주문을 넣은 것부터 하나씩 체크할 수 있고 이 체크 상태는 직원 화면에도 그대로 보입니다. 상단 "최근 7일" 칩으로 지난 일주일 중 아무 날짜나 바로 눌러 그날 누가 뭘 요청했는지 확인할 수 있고, 그 이전 날짜도 달력에서 선택하면 계속 볼 수 있습니다 (기록은 자동으로 지워지지 않습니다). "공유하기"로 카카오톡 등에 바로 전송
- **자재 관리** (사장님 화면에서만 진입 가능): 새 메뉴가 생기거나 단종된 자재가 있을 때 쓰는 화면으로, **추가/수정/삭제**와 순서 변경이 가능합니다. 소분류는 별도로 "만드는" 화면이 없고, **소분류 칸에 기존에 없는 이름을 입력해서 자재를 추가하면 그 이름으로 새 소분류가 그 자리에서 생깁니다** (예: "콜드브루류"라고 입력하고 추가하면 그 소분류가 바로 생김). 기존 소분류 목록은 칩으로 보여줘서 탭하면 그대로 재사용할 수 있어요. 매머드 익스프레스 커피의 실제 자재 목록(75개 품목)이 기본 카탈로그로 이미 들어있어요

컬러는 잉크블랙 + 골드 톤의 프리미엄한 느낌으로 디자인했습니다. 설치 없이 각자 스마트폰 브라우저에서 링크를 열고 **홈 화면에 추가**하면 앱처럼 사용할 수 있습니다.

## ⚠️ "연결에 실패했어요" / 전화번호를 넣어도 안 넘어가요

**아직 정상입니다.** 이 앱은 데이터를 저장할 Firebase 프로젝트를 아직 연결하지 않은 상태라, `public/js/firebase-config.js`에 `YOUR_API_KEY` 같은 임시값이 그대로 들어있습니다. 이 상태에서는 로그인/발주 저장 등 데이터가 오가는 모든 기능이 "연결에 실패했어요"로 나옵니다 — 화면 레이아웃과 흐름만 미리 볼 수 있는 상태예요. 아래 1~3단계를 완료해서 실제 Firebase 프로젝트를 연결해야 정상적으로 로그인되고 데이터가 저장/동기화됩니다.

## 1. Firebase 프로젝트 만들기 (최초 1회, 사장님/본인 구글 계정 필요)

1. https://console.firebase.google.com 접속 → 로그인 → **프로젝트 추가**
2. 프로젝트 이름 입력 (예: `cafe-order`) → 애널리틱스는 꺼도 무방 → 프로젝트 만들기
3. 왼쪽 메뉴에서 **Firestore Database** → **데이터베이스 만들기** → 위치는 `asia-northeast3(서울)` 선택 → **프로덕션 모드**로 시작 (규칙은 이 저장소의 `firestore.rules`로 나중에 교체합니다)
4. 왼쪽 메뉴에서 **빌드 → Authentication** → **시작하기** → 로그인 방법 탭에서 **익명(Anonymous)** 사용 설정으로 켜기 (이건 SMS 인증이 아니라 Firestore 접근을 보호하기 위한 내부용 인증이라 비용이 들지 않습니다)
5. 프로젝트 개요 옆 톱니바퀴 → **프로젝트 설정** → 아래로 스크롤 → **내 앱** → 웹 아이콘(`</>`) 클릭 → 앱 닉네임 입력 (Firebase Hosting 설정 체크는 안 해도 됨) → 앱 등록
6. 화면에 나오는 `firebaseConfig` 객체 값을 복사

## 2. 이 프로젝트에 설정값 붙여넣기

`public/js/firebase-config.js` 파일을 열어서 1-6에서 복사한 값을 그대로 붙여넣으세요.

```js
export const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "...",
};
export const STORE_NAME = "매머드 익스프레스 커피"; // 원하는 매장 이름으로 변경
```

(PIN은 여기에 넣지 않습니다 — 앱에서 처음 "사장님"으로 등록하는 사람이 직접 PIN을 만들게 되어 있어요. 아래 "계정 시스템" 참고.)

`.firebaserc` 파일의 `YOUR_PROJECT_ID`도 실제 프로젝트 ID로 바꿔주세요 (Firebase 콘솔 프로젝트 설정에서 확인 가능).

## 4. 다같이 사용하기

1. **사장님 폰**에서 먼저 위 링크를 열고 본인 휴대폰 번호 입력 → 처음이라 등록 화면이 뜨면 이름 입력 → "사장님" 선택 → **처음이라 PIN을 새로 만드는 화면**이 뜹니다. 원하는 숫자(4자리 이상)를 두 번 입력해서 PIN을 만드세요 — 이 PIN이 앞으로 사장님 계정의 유일한 열쇠입니다. → **자재 관리**에서 카탈로그를 확인/추가/삭제합니다 (75개 기본 품목이 이미 들어있어요).
2. 공유 버튼 → **"홈 화면에 추가"** (아이폰: 하단 공유 아이콘 → 홈 화면에 추가 / 안드로이드 Chrome: 우측 상단 점 3개 → 앱 설치 또는 홈 화면에 추가).
3. **직원 폰**에서도 같은 링크를 열고 각자 본인 번호 입력 → 처음이면 이름 입력 후 "직원" 선택 → 홈 화면에 추가.
4. 매일 직원이 자기 화면에서 대분류 → 소분류 → 자재를 눌러 내려가며 "정상 발주" 또는 "긴급"으로 체크 → **"기본자재 발주 요청하기" / "식자재 발주 요청하기" 버튼을 눌러 제출** → 사장님은 **오늘 발주** 화면에서 제출된 항목만 실시간으로 확인, 필요하면 **공유하기**로 카카오톡에 붙여넣기.

## 계정 시스템 (휴대폰 번호 로그인)

- Firestore의 `accounts` 컬렉션에 `{전화번호: {이름, 역할}}` 형태로 저장됩니다. 문자 인증(SMS OTP)은 사용하지 않고, 번호를 입력하는 것만으로 그 번호의 계정으로 로그인됩니다 — 즉 실제 본인 확인은 하지 않는 "간편 등록" 방식입니다.
- 전화번호는 `010`으로 시작하는 11자리(010 + 8자리)만 입력할 수 있습니다.
- **같은 번호로 로그인하면 다른 기기에서도 항상 같은 이름·같은 역할**로 들어가지고, 접속할 때마다 Firestore에서 최신 정보를 다시 불러오기 때문에 사장님이 나중에 누군가의 역할을 바꾸면 다음 로그인부터 바로 반영됩니다.
- **PIN은 코드에 없습니다.** 앱에서 아무도 "사장님"으로 등록한 적이 없으면, 처음 "사장님"을 선택하는 사람에게 "PIN 만들기" 화면이 뜨고, 그때 직접 정한 PIN이 Firestore(`config/ownerPin`)에 저장됩니다. 그 뒤로는 새 번호로 "사장님"을 등록하거나, 이미 사장님으로 등록된 번호로 다시 로그인할 때 모두 그 PIN을 입력해야 합니다.
- PIN을 잊어버렸다면, Firebase 콘솔 → Firestore Database → `config` 컬렉션 → `ownerPin` 문서에서 `pin` 값을 직접 확인하거나 새 값으로 바꿀 수 있습니다.
- 각 화면 우측 상단의 **로그아웃**을 누르면 그 기기에서 로그아웃되고, 처음 번호 입력 화면으로 돌아갑니다 (계정 자체가 지워지는 건 아니라 같은 번호로 다시 로그인하면 원래대로 돌아옵니다).
- 직원 이름이 바뀌었거나 실수로 다른 역할로 등록했다면, 사장님이 Firebase 콘솔의 Firestore Database에서 `accounts/{전화번호}` 문서를 직접 열어 `name`/`role` 값을 수정하면 됩니다.

## 발주 요청 제출 방식

- 직원이 자재를 체크하는 것과 그게 사장님 화면에 올라가는 것은 **별개의 단계**입니다. 체크만 한 상태는 그 직원 기기에만 "미제출"로 남아있고, **"○○ 발주 요청하기" 버튼을 눌러야** Firestore에 저장되어 사장님과 다른 직원 모두에게 보입니다.
- 기본자재/식자재는 각각 독립적으로 제출합니다 — 기본자재만 먼저 제출하고 식자재는 나중에 제출해도 되고, 그 반대도 가능합니다.
- 사장님 화면(오늘 발주)에는 **제출된 항목만** 나타나며, 기본자재/식자재로 나눠 자동으로 합쳐서 보여줍니다.
- 소분류 화면 하단의 **"장바구니 담기"** 버튼은 그 화면에서 고른 항목들을 확인하는 용도로, 실제 전송은 여전히 대분류 단위의 "발주 요청하기"에서 이뤄집니다.
- **한 번 제출된 자재는 잠깁니다.** 이미 "제출됨" 표시가 붙은 자재는 정상/긴급 버튼과 메모가 비활성화되어 직원이 다시 취소하거나 바꿀 수 없습니다 — 사장님께 이미 전달된 요청이 조용히 사라지는 걸 막기 위함입니다. 아직 제출 전(미제출)인 항목은 자유롭게 바꾸거나 취소할 수 있고, 다른 자재를 새로 선택하는 것도 항상 가능합니다.
- 다만 잘못 제출한 경우를 위해, 제출된 항목 옆에 **"삭제" 버튼**이 따로 있습니다. 확인 팝업을 한 번 거쳐 누르면 그 항목이 즉시 삭제되어 사장님 화면에서도 바로 사라집니다 (평소 토글로는 못 바꾸지만, 실수를 되돌리는 명시적인 삭제는 항상 가능합니다).

## 수량 / 정상·긴급·품절 3단계

- 자재를 고를 때 **정상 발주(2-3일 여유) / 긴급(내일 당장 없음) / 품절(지금 재고 없음)** 중 하나를 선택합니다. 버튼 아래 작은 문구로 각 상태의 의미를 바로 보여줍니다. 긴급과 품절은 둘 다 빨간색으로 표시되어 한눈에 "급한 항목"으로 구분됩니다.
- **수량**은 메모(비고)와 별개의 칸입니다 — "2박스", "1kg"처럼 자유롭게 적을 수 있고, 담은 목록·사장님 화면 양쪽에 자재명 옆 작은 표시로 나타납니다.

## 주문완료 체크 (사장님 → 직원 동기화)

- 사장님이 발주 리스트를 보고 실제로 주문을 넣을 때, 각 항목 옆 **"주문완료" 체크박스**로 하나씩 표시할 수 있습니다.
- 체크만으로는 아직 확정되지 않습니다 — 여러 개를 체크한 뒤 목록 맨 아래 **"체크하고 직원에게 공유" 버튼**을 눌러야 실제로 저장되고 직원 화면에 반영됩니다.
- **한 번 공유된 체크는 잠깁니다.** 체크박스가 비활성화되고 라벨도 "공유됨"으로 바뀌어서, 실수로 다시 해제할 수 없습니다. 공유 전(아직 버튼을 안 누른) 체크는 자유롭게 켰다 껐다 할 수 있습니다.
- 공유된 항목은 Firestore에 저장되기 때문에 **직원 화면(담은 목록/자재 상세)에서도 "✓ 사장님이 주문 완료 처리했어요"로 동일하게 보입니다.**

## 소분류 안 자재 순서 (수동 정렬)

- 각 소분류 안에서 자재가 보이는 순서는 **사장님이 자재 관리 화면에서 직접 정합니다.** 자재 목록의 각 항목 왼쪽에 있는 **▲ / ▼ 버튼**으로 바로 위·아래 자재와 순서를 바꿀 수 있어요 (맨 위/맨 아래 항목은 해당 방향 버튼이 비활성화됩니다).
- 새로 추가한 자재는 기본적으로 그 소분류의 맨 아래에 들어가고, 필요하면 위로 올려서 원하는 자리에 배치하면 됩니다.
- 이 순서는 **직원의 자재 선택 화면과 사장님의 발주 리스트 화면 양쪽에서 동일하게 적용**되어서, 사장님이 리스트를 볼 때도 자재 관리에서 정해둔 순서 그대로 보입니다.
- (이전에 있던 "주문 많이 한 자재가 자동으로 위로 올라가는" 자동 정렬은 수동 정렬과 함께 쓰면 서로 충돌해서 헷갈리기 때문에, 이번에 수동 정렬로 대체했습니다.)

## 발주 사이트 바로가기

- 사장님 화면의 발주 리스트 아래에 **"발주 사이트 바로가기"** 버튼이 있습니다 (기본값: 쿠팡). 누르면 새 탭으로 해당 사이트가 열리고, 모바일에서 앱이 깔려있으면 보통 그 앱으로 바로 연결됩니다.
- 자주 쓰는 사이트를 추가/변경하려면 `public/js/firebase-config.js`의 `QUICK_ORDER_LINKS` 배열에 `{ label: "이름", url: "주소" }` 형태로 원하는 만큼 추가하면 됩니다.

## 알림

- **사장님 화면**: 상단의 "알림 켜기"를 누르면, 직원이 그날 새로 "발주 요청하기"를 눌러 제출할 때마다 알림이 옵니다.
- **직원 화면**: 마찬가지로 "알림 켜기"가 있고, 켜두면 사장님이 항목을 체크하고 **"체크하고 직원에게 공유"**를 누르는 순간 "사장님이 주문완료 처리했어요" 알림이 옵니다.
- 각자 자기 폰에서 알림 켜기를 눌러야 하고, 사장님/직원 모두 서버나 별도 비용 없이 브라우저 자체 알림(Notification API)만 사용하는 방식이라, **그 폰에서 이 앱(브라우저 탭 또는 홈 화면 아이콘)이 완전히 종료되지 않고 열려 있거나 최근까지 백그라운드에 있어야** 알림이 옵니다. 앱을 스와이프해서 완전히 꺼버리면 알림이 오지 않을 수 있어요.
- 앱을 완전히 꺼도 오는 "진짜 푸시 알림"이 필요해지면, Firebase Cloud Functions + FCM으로 전환할 수 있습니다 — 다만 Firebase Blaze(사용량 기반) 요금제 연결이 필요합니다. 필요해지면 말씀해주세요.

## 기록 보관 & 실시간 동기화

- **보관 기간**: 발주 기록은 날짜별로 Firestore에 저장되고, **자동으로 삭제되는 로직이 없습니다** — 최소 7일은 물론, 그 이전 기록도 계속 남아있고 사장님 화면의 날짜 선택으로 언제든 다시 조회할 수 있습니다. "최근 7일" 칩은 자주 보는 최근 기록에 빠르게 접근하기 위한 단축 버튼일 뿐, 그 이후 기록을 지우는 기능이 아닙니다.
- **실시간 동기화**: 직원이 자재를 담는 순간 Firestore 실시간 리스너를 통해 사장님 화면에 새로고침 없이 즉시 반영됩니다. 반대로 사장님이 자재 카탈로그를 수정하면 직원 화면에도 바로 반영됩니다.
- **"오늘" 기준 시간대 고정**: 기기의 시간대 설정과 상관없이 앱 내 모든 "오늘" 계산은 한국 시간(KST) 기준으로 고정되어 있어서, 직원이 해외 로밍 중이거나 폰 시간대 설정이 다르더라도 모두 같은 날짜를 보게 됩니다.
- **코드 업데이트 반영**: `firebase.json`에서 html/js 파일에 `no-cache` 헤더를 걸어뒀고, 서비스워커도 매번 네트워크에서 새로 받아오도록 설정해서, 배포하면 다음에 앱을 열 때(또는 "새로고침" 버튼) 바로 최신 코드가 반영됩니다.

## 참고 / 한계

- 휴대폰 번호 로그인은 "번호를 아는 사람"이 아니라 "번호를 입력한 사람"을 신뢰하는 방식이라, 문자로 본인 확인을 하는 진짜 인증은 아닙니다. 직원끼리 서로의 번호를 입력해 로그인하는 것을 막을 수는 없어요. (진짜 SMS 인증으로 바꾸려면 Firebase Blaze 유료 요금제 연결과 문자 발송 비용이 필요합니다 — 필요해지면 언제든 전환해드릴 수 있습니다.)
- 사장님 계정만 직접 만든 PIN으로 한 번 더 보호되어 있습니다. PIN과 앱 링크를 외부에 공개하지 마세요.
- 발주 기준 수량 자동 계산은 없고, 직원이 자재별로 "정상 발주 / 긴급"을 직접 선택해서 담는 방식입니다.
- Firebase 무료 요금제(Spark) 사용량 안에서는 비용이 발생하지 않습니다 (하루 수십~수백 건 수준의 소규모 매장 사용은 충분히 무료 범위 안입니다).
